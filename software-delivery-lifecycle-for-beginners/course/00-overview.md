# Course Overview

**Software Delivery Lifecycle for Beginners · Coraxshift DevOps Academy** · ⏱️ 10 minutes

## 👋 Welcome

Writing code is only one part of delivering software. Someone has to decide **what** to build, check that it **works**, put it in front of real users, and **fix it fast** if something goes wrong. That whole journey is the **software delivery lifecycle**, and DevOps engineers live inside it every day.

Think of a bakery:

| In the bakery | In software |
|---|---|
| A customer asks for a birthday cake | A **request** or idea |
| You write down size, flavour and pickup time | **Requirements** and acceptance criteria |
| You bake it | **Build** |
| You taste it and check the writing on top | **Test** |
| You box it and hand it over | **Release** |
| The cake is dropped, so you bake a quick replacement | **Rollback** and recovery |
| You ask whether they enjoyed it | **Learn and improve** |

```text
idea ─▶ plan ─▶ build ─▶ test ─▶ review ─▶ release ─▶ watch ─▶ improve
  ▲                                                               │
  └───────────────────────────────────────────────────────────────┘
```

> 💡 This course needs **no coding**. You will write plain text files, run a few simple commands, and think like someone who delivers software safely.

## 🎯 What you will be able to do

- Turn a vague idea into a clear **user story** with **acceptance criteria**
- Decide what is **in scope** and **out of scope**, and name the risks
- Break a feature into small, reviewable tasks
- Write test cases for normal, empty and failure situations
- Explain unit, integration and end-to-end tests with everyday examples
- Write a bug report someone else can act on
- Prepare a release checklist, a release note and a rollback plan
- Mark a release with a Git tag and go back to a safe version

## 🗺️ How the course works

| Step | What you do | Time |
|---|---|---|
| 📝 Class 1 | From idea to plan | 2 h |
| 🧪 Class 2 | Testing what you build | 2 h |
| 🚀 Class 3 | Release and rollback | 2 h |
| 🧩 Assignment | Plan a feature from idea to rollback | 2 to 3 h |
| 🎭 Role play | Explain delivery to a business owner | 15 min |
| 📝 Quiz | 12 questions, 90% earns the badge | 20 min |

Every step follows the same five parts: **Why this matters**, **Run it**, **What it does**, **What you should see**, **If yours looks different**.

## ✅ Before you start

This course builds on **Git and GitHub for Beginners**. You should be comfortable with `git add`, `git commit`, branches and a portfolio repository on GitHub.

## 🛡️ Ground rules

- Practise only in your own Codespace and your own repositories.
- Never put passwords, tokens or customer data in a file, an issue or a bug report.
- Small changes are safer than big ones. That idea runs through the whole course.
