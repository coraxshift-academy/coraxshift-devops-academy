# Course Overview

**Git and GitHub for Beginners · Coraxshift DevOps Academy** · ⏱️ 10 minutes

## 👋 Welcome

Have you ever saved a file as `report-final.docx`, then `report-final-v2.docx`, then `report-final-REALLY-final.docx`? Git is the grown-up fix for that. It remembers every version of your work, lets you go back to any of them, and lets several people work on the same project without overwriting each other.

**GitHub** is the website where that history lives online, so you can share it, back it up and show it to employers and clients.

Think of it like this:

| Everyday idea | Git idea |
|---|---|
| A notebook where you write down every change | A **repository** (repo) |
| Taking a photo of your work at a moment in time | A **commit** |
| Choosing what goes into the next photo | The **staging area** |
| Trying an idea on a copy, without risking the original | A **branch** |
| Asking a colleague to check before it goes in | A **pull request** |

## 🎯 What you will be able to do

- Create a repository and save your work in clear, well-named commits
- See exactly what changed, and what is about to be saved
- Keep secrets and junk out of Git with `.gitignore`
- Try ideas safely on a branch, then bring them back with a merge
- Fix a merge conflict calmly
- Undo mistakes in the safe way (and know which undo is dangerous)
- Put your work on GitHub, and open a pull request
- Build a portfolio repository you can show to an employer

## 🗺️ How the course works

| Step | What you do | Time |
|---|---|---|
| ✍️ Class 1 | Your first repository: save, inspect, ignore | 2 h |
| 🌿 Class 2 | Branches, merging, conflicts and undo | 2 h |
| 🌍 Class 3 | GitHub, pull requests and teamwork | 2 h |
| 🧩 Assignment | Build your portfolio and send a pull request | 2 to 3 h |
| 🎭 Role play | Explain Git to a non-technical person | 15 min |
| 📝 Quiz | 12 questions, 90% earns the badge | 20 min |

Every step follows the same five parts: **Why this matters**, **Run it**, **What it does**, **What you should see**, **If yours looks different**.

> [!TIP]
> Type every command yourself. Git feels strange for the first hour and natural after the second class.

## 🛡️ Ground rules

- Practise only in your own Codespace and your own repositories.
- Never put passwords, tokens, keys or `.env` files into Git. Once they are saved in history, they are very hard to remove.
- If a message looks scary, stop and read it. Git messages usually tell you exactly what to do next.
