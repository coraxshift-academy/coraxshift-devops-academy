# Week 4: Git and GitHub

**Project:** CoraxReads
**Goal:** Make small, reviewable changes and collaborate without losing work.

## What you will ship

- A repository with a clear README and `.gitignore`.
- A feature branch, a small commit, and a pull request.
- A documented merge-conflict resolution.

## Three classes

1. **Git basics:** working tree, staging area, commits, and history.
2. **Team workflow:** branches, pull requests, code review, and conflicts.
3. **Recovery and hygiene:** restore, revert, ignore rules, and safe collaboration.

```text
edit -> inspect diff -> stage selected files -> commit -> push branch -> review PR
```

Git is the notebook of changes; GitHub hosts the notebook and review conversation.

## Before you start

Install Git and configure your name/email for commits. Never put passwords or access tokens in repository files or commit messages.

## Completion check

- You can show the difference between unstaged and staged changes.
- Your commit contains only the intended files.
- You can explain how a pull request is reviewed and merged.
- You know the difference between `restore` (discard local edits), `revert` (new undo commit), and `reset` (move a branch pointer).
