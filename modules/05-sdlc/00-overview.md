# Week 5: Plan, Build, Test, Release

**Project:** CoraxReads
**Goal:** Turn a feature idea into a small, testable, reversible change.

## What you will ship

- One feature issue with a user story and acceptance criteria.
- A small implementation plan and test checklist.
- A release note and rollback plan.

## A bookstore example

Feature: a visitor can see a list of books. The acceptance check is not "it works"; it is specific: "Given books exist, when the visitor opens the catalog, book titles and prices are shown."

## Three classes

1. **Requirements:** user, problem, scope, and acceptance criteria.
2. **Testing:** test layers, reproducibility, and a useful bug report.
3. **Release operations:** versioning, release checklist, monitoring, and rollback.

```text
idea -> issue -> plan -> change -> test -> review -> release -> observe -> improve
```

## Completion check

- Work is small enough to review.
- Acceptance criteria describe observable behavior.
- Tests match the criteria.
- Release notes say what changed; rollback steps are practical.
