# Role Play: Explain Git to a Book Author

**Git and GitHub for Beginners · Coraxshift DevOps Academy** · ⏱️ 15 minutes (after the assignment)

## 🎭 The scenario

A friend is writing a novel with a co-author. They email a Word file back and forth. Last week one of them overwrote the other's chapter, and three days of work disappeared. Their files are called `novel-v7-final-FINAL-edited.docx`.

She asks you:

> *"My cousin says programmers never lose work because of something called Git. What is it? How is it different from saving the file? And is GitHub the same thing?"*

She is clever, but she is not technical. She will stop you if you use a word without explaining it.

## 🎯 Your job

Explain Git in **about one minute**, in plain words, with **no unexplained jargon**. Make sure you answer her three questions:

1. What is Git?
2. How is it different from just saving the file?
3. Is GitHub the same thing?

## 💡 Ideas to build on

- Git is like a notebook that remembers **every version** you chose to keep, with a note on why.
- Saving overwrites. Git **adds**, so the old version is never lost.
- A **branch** lets each author work on a private copy, and then the two copies are joined together carefully. If both changed the same sentence, Git asks a human which one to keep.
- **GitHub** is a website that stores a copy of that notebook online. Git is the tool. GitHub is the shelf.

> 📖 **From my café:** In my café, HandyCafe recorded every customer session, so I could tell what had happened and what was owed. Git does that for your work. Every change is saved with a note, so you can see what happened, when, and go back if something goes wrong.

## 🧪 A starting script (say it in your own words)

> "Git is a notebook for your files. When you save a document, the new version replaces the old one. With Git, every time you reach a good point, you take a snapshot and write a short note about it. The old snapshots stay, so you can go back to any day. You and your co-author can also each work on your own copy, and Git joins the two together. If you both changed the same sentence, it does not guess. It asks you. GitHub is just a website where that notebook is kept online, so both of you can reach it and nothing is lost if a laptop breaks."

Do **not** read it out. Say it in your own words. If you read it out, it will not help you.

## ✅ Pass check

- [ ] You spoke for about one minute
- [ ] You answered all three of her questions
- [ ] You did not use "repository", "commit", "branch" or "merge" without explaining them
- [ ] You used one everyday comparison
- [ ] The listener could repeat your explanation in her own words
