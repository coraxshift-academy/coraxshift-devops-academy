# Quiz: Software Delivery Lifecycle for Beginners

**Coraxshift DevOps Academy · Learn. Build. Deploy. Grow.**

🏅 **12 questions, about 20 minutes.** 8 are *Choose ONE*, 4 are *Choose ALL that apply*.
Score **90% (11 out of 12) or more** to earn your **Software Delivery Lifecycle for Beginners badge**. Below that, you get one retake after reviewing Class 1 and Class 2.

Every question comes from something you practised in this course. Answer all of them **before** you look at the answers.

## Questions

**Q1. Choose ONE.** Which is a well-written user story?
- A. Build a good website
- B. Make it fast
- C. As a shopper, I want to see books with prices, so that I can decide what to buy
- D. Use a database

**Q2. Choose ONE.** What do acceptance criteria describe?
- A. How the code is written
- B. What a person can check to confirm the feature works
- C. Who will be blamed if it fails
- D. How much the project costs

**Q3. Choose ONE.** What does "out of scope" protect you from?
- A. Slow computers
- B. Bugs in Git
- C. A small job quietly growing into a huge one
- D. Having to write tests

**Q4. Choose ONE.** Which test case is complete?
- A. "Test the list"
- B. "Check it works"
- C. "Make sure it is good"
- D. Start: data file is empty. Action: run the script. Expected: the message "No books yet"

**Q5. Choose ONE.** Which type of test checks the whole journey as a shopper sees it?
- A. Unit test
- B. End-to-end test
- C. Integration test
- D. Spelling test

**Q6. Choose ONE.** Your tests all pass, but shoppers see prices without a currency. What is the best explanation?
- A. Tests never find bugs
- B. The shoppers are wrong
- C. No test checked the price format, so a passing test only proves what it was written to prove
- D. The tests were run too slowly

**Q7. Choose ONE.** A release goes live and prices are wrong. What is the first priority?
- A. Find out who made the mistake
- B. Restore working service by rolling back to the last good version
- C. Delete the repository
- D. Wait to see if it fixes itself

**Q8. Choose ONE.** Why is `git revert` usually safer than `git reset --hard` on shared work?
- A. It is faster to type
- B. It deletes the bad commit from everyone's computer
- C. It adds a new commit that cancels the bad one, so history stays intact for the whole team
- D. It runs the tests for you

**Q9. Choose ALL that apply.** Which belong in a good bug report?
- A. Exact steps to reproduce it
- B. What you expected
- C. What actually happened
- D. A real customer's password for "evidence"

**Q10. Choose ALL that apply.** Which belong on a release checklist?
- A. All tests pass
- B. A second person reviewed the change
- C. No secrets in the files
- D. Skip the rollback plan because releases are usually fine

**Q11. Choose ALL that apply.** What does a Git tag such as `v0.1.0` give you?
- A. A permanent label on one exact version
- B. A way to know which version was last known good
- C. A guarantee the code has no bugs
- D. A clear point to refer to in a release note

**Q12. Choose ALL that apply.** Which statements about rollback are true?
- A. A rollback plan should be written before you need it
- B. Rolling back the program may not roll back changed data
- C. Rollback is only needed for big companies
- D. After rolling back, you should still investigate the cause
